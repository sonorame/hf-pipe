# Проверка маршрута Codex / Kilo, 2026-10-05

Активный подписанный пакет хопа: `a3b26f918be515b1`, protocol `2`. Проверены фактические пути RTC worker на dirty и clean, а не только указатели `current`. Единица выкладки — полный пакет через Matrix staging, проверку подписи и активацию.

В пакет включены разрешённые домены OpenAI и проверенный Duplex mux. Исправлено завершение TCP ответа: STREAM CLOSE ожидает отправки последних DATA, а clean сохраняет буфер до чтения потребителем. Регрессии проверяют очередность EOF и передачу 1 MiB медленному потребителю.

Через CONNECT на clean получены HTTP ответы от `api.openai.com`, `chatgpt.com/backend-api/codex/models` и `api2.cursor.sh` (для последнего HTTP 200). curl/Schannel требует учитывать недоступность прямого выхода для проверки отзыва сертификатов; тест с `--ssl-no-revoke` сохраняет проверку цепочки и имени сертификата.

Kilo `7.3.54` имеет OpenAI OAuth browser/headless методы. Созданы отдельные данные VS Code `~\.hf-pipe\vscode-kilo-codex`, запуск с `--proxy-server`, настройки `http.proxy` и процессные proxy переменные. Прямой provider `openai`, модель `gpt-5.3-codex` взята из каталога установленного backend. Существующий локальный LM Studio и его конфигурация сохранены. Используется существующий `~\.config\kilo\fullchain.pem`, TLS проверка включена. Headless запрос авторизации прошёл через трубу: dirty зарегистрировал `egress open ... auth.openai.com 443`.

Полный `npm test` повторён после изменения mux: 246 тестов, 241 passed, 5 failed. Четыре ошибки вызваны не отвечающим PowerShell на dirty (DPAPI и архивирование), одна — личным путём в ранее изменённом `scripts/kes-castrate-trusted.ps1`. Эти проверки не скрыты и не исключены. Подпись staging пакета независимо проверена существующим публичным ключом.

Пользователь завершил OpenAI OAuth. Реальный запрос из Kilo backend на clean к `openai/gpt-5.5` вернул `PIPE_OK`, `error: null`; свежие соединения `chatgpt.com:443` подтверждены в логе dirty. Первоначальный выбор `gpt-5.3-codex` отклонён OpenAI для ChatGPT sign-in, поэтому финальный launcher и настройки используют проверенную `gpt-5.5`.

Для устойчивой проверки TLS создан отдельный `~\.hf-pipe\kilo-codex-ca.pem`: прежний bundle clean дополнен публичными CA из системно проверенных цепочек OpenAI на dirty. Глобальное доверие и TLS validation не отключались. Финальный launcher передаёт этот bundle backend Kilo. Маршрут Kilo → труба → dirty → OpenAI проверен; перечисленные выше пять ошибок полного тестового набора остаются ограничением проверки репозитория.
