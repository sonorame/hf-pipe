# Доверие между clean и dirty

Matrix подтверждает отправителя-аккаунт, но поле `from` внутри сообщения само по себе не подтверждает устройство. Схема `hf:2` добавляет отдельную Ed25519-подпись устройства. Проверка выполняется до передачи SDP/ICE RTC worker и до обработки release controls.

В подписанном immutable release находится `peer-trust.json`: `version:1`, `dirty` и `clean`, каждый с `userId`, `deviceId`, `publicKey` (PEM Ed25519). Доверие к этим открытым ключам наследуется от проверенной подписи release. Имя устройства и Matrix device discovery не используются для авторизации или выбора адресата.

На каждой машине отдельная identity хранится в `secretsDir()/peer-identity/release-private.dpapi` и защищена Windows DPAPI текущего пользователя. Это отдельная пара, не ключ подписи пакетов. Private keys не входят в release, не передаются между машинами и не печатаются. `node scripts/enroll-peer.mjs` создает или проверяет identity и печатает только открытый дескриптор текущего Matrix устройства. Оператор получает оба дескриптора через уже доверенный локальный/clean-pc канал, объединяет их в manifest и передает `buildRelease({peerTrust})`. Новый Matrix device требует явного повторного enrollment и нового подписанного release.

Подписываются точные UTF-8 байты JSON payload с доменным префиксом `hf-pipe peer envelope v1\0`; payload и подпись передаются base64. Payload связывает lane/frame, Matrix user/device отправителя и адресата, время и случайный nonce. Приемник проверяет реальный `event.getSender()`, pinned public key, обе identity, допустимые lane, возраст/отклонение времени не более пяти минут и лимит payload 40 KB. Неподписанная схема `hf:1` не принимается. Протокол 3 следует выкладывать на обе стороны совместно; downgrade не включает обход проверки.

Nonce сохраняется до исполнения сообщения в mutable `local/peer-replay-{side}.json`. Срок хранения перекрывает окно допустимого времени; максимум 4096 записей, новые сообщения при заполненном кеше отклоняются. Повторное сообщение после рестарта также не исполняется. Недоступная запись replay cache приводит к отказу обработки. Очистка identity/replay cache вручную не является способом восстановления сети.

Граница доверия: компрометация Windows пользователя или release signing authority позволяет заменить доверенные ключи. Подпись сигнализации не заменяет контроль доступа к локальному HTTP интерфейсу и не решает ресурсные лимиты egress. Изменение подписанного SDP защищает согласуемый DTLS fingerprint; никаких изменений проверки TLS/DTLS не требуется.

Проверки: неверный реальный sender, чужой ключ того же аккаунта, изменение signed bytes, неправильный адресат, просроченное сообщение, unsigned legacy, повтор nonce после restart, ошибка записи replay cache и oversized payload отклоняются. Live приемка дополнительно проверяет одинаковый trust manifest обеих сторон и новый clean-pc/Kilo путь после coordinated activation.
